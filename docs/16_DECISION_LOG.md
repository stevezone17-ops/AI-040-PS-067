## ADR-001 — Selection of Python 3.10+ with Standard-Library Runtime
- **Date:** 2026-11-25 | **Status:** Proposed (Pending Team Confirmation)
- **Decision:** Implement the engine in **Python 3.10+** using only the Python standard library at runtime, with `pytest` and `ruff` restricted to development/testing dependencies.
- **Alternatives Considered:** (1) Java 17 / Maven; (2) C++20; (3) Python with heavy third-party OR/data libraries (`pandas`, `ortools`, `pydantic`).
- **Rationale:** All three AIML undergraduate team members are fluent in Python, maximising viva explainability and live-code modifiability (`15` marks combined). Python 3.10+ provides `dataclasses(frozen=True, slots=True)` and union types natively, while avoiding external packages eliminates environment fragility during automated grading (`~0.35 s` runtime on expected scale needs no C++ compilation).
- **Consequences:** Developers must write explicit CSV/JSON validators in `io/` rather than relying on `pydantic`, keeping validation logic 100% transparent.

## ADR-002 — Straightforward 5-Layer Modular Architecture (14 Components)
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Structure `src/exam_engine/` into 5 unidirectional layers encompassing the 14 cohesive domain/adapter components defined in [`07_SYSTEM_ARCHITECTURE.md`](07_SYSTEM_ARCHITECTURE.md), avoiding microservices, web APIs, or hexagonal over-abstraction.
- **Alternatives Considered:** (1) Monolithic single-script scheduler; (2) FastAPI + SQLite client-server architecture; (3) Event-sourced plugin bus.
- **Rationale:** A single script fails the `20`-mark Domain Design rubric and creates Git merge bottlenecks across 3 developers. Conversely, FastAPI/microservices violate scope rules and add zero grading value. Clean Python packages with pure functions give clean Git ownership boundaries (`scheduling/`, `allocation/`, `invigilation/`, `changes/`, `validation/`).
- **Consequences:** Cross-package calls must pass typed domain objects defined in `domain/`.

## ADR-003 — Strict Adherence to Prescribed Deterministic Greedy Heuristic (`BR-03`)
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Implement initial timetabling strictly via `BR-03`'s sort order `(-enrolment_count, -credits, course_code)` and two-pass earliest-session scan (`ALG-06`), augmented with exact `ALG-08` hall packability verification and `ALG-10` small-course pair co-scheduling—never replacing it with ILP, CP-SAT, simulated annealing, or backtracking graph-colouring.
- **Alternatives Considered:** (1) Google OR-Tools CP-SAT global solver; (2) DSATUR dynamic degree-of-saturation heuristic; (3) Backtracking search reordering large courses.
- **Rationale:** `BR-03` explicitly prohibits replacing the prescribed heuristic because automated grading compares output against deterministic reference outputs generated by `BR-03`.
- **Consequences:** Does not guarantee global optimality on pathological adversarial graphs; hard-infeasible courses are transparently reported as `UNSCHEDULED_COURSE`.

## ADR-004 — Strict Separation of Hard Constraints, Soft Gap Fallback & Resource Shortages
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Enforce a 7-way outcome taxonomy (`06_CONSTRAINT_CATALOGUE.md`) where **only** `BR-02` core-course gap degrades to `SOFT_VIOLATION` (`BR-03`) and **only** `BR-08` invigilator exhaustion yields `UNSTAFFED` (`RESOURCE_SHORTAGE`); hard rules (`BR-01`, `BR-04`, `BR-05`, `BR-06`, `BR-07` eligibility, `BR-12`) are inviolable.
- **Alternatives Considered:** Penalty-weighted soft objective function allowing minor student clashes or adjacent seating under congestion.
- **Rationale:** Relaxing hard constraints corrupts exam integrity and fails the `40`-mark Business-Rule Correctness gate.
- **Consequences:** Impossible inputs produce explicit `UNSCHEDULED_COURSE` or `REJECTED_*` diagnostics rather than silent rule breaches.

## ADR-005 — Command-File Driven CLI Execution Without Interactive State
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Operate purely via deterministic CLI file inputs (`--input-dir`, `--commands`, `--output-dir`, optional `--resume-state`) with structured exit codes (`0`, `2`, `3`).
- **Alternatives Considered:** Interactive REPL shell or REST endpoint accepting live JSON mutations.
- **Rationale:** Directly satisfies official problem statement (*"command-file driven. No UI is required"*) and enables one-command regression testing.
- **Consequences:** Multi-batch incremental runs persist state via `schedule_state.json`.

## ADR-006 — Pure In-Memory Domain Model With Single-Source-of-Truth `Enrolment`
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Hold all master registries and schedule state in memory using frozen Python dataclasses, with `Enrolment` acting as the sole canonical owner of student-course relationships (`08_DOMAIN_MODEL.md`).
- **Alternatives Considered:** (1) Embedded SQLite database with SQL joins; (2) Bidirectional mutable lists (`Student.courses` + `Course.students`).
- **Rationale:** At `2,500` students and `12,500` enrolments, the entire memory footprint is `< 15 MB`. SQLite adds SQL schema ceremony and slows candidate cloning, while bidirectional mutable lists risk synchronisation bugs during `BR-11` late registration rollbacks.
- **Consequences:** `ProblemRegistry` builds immutable indexed dictionary views on startup and on late-registrant upserts.

## ADR-007 — Precomputed Dual-Map Student Conflict Graph (`ALG-03`)
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Precompute an undirected course conflict graph with two symmetric edge sets—`same_session_forbidden` and `same_day_forbidden` (encoding `BR-01` and `BACKLOG_CONSENT` / `AS-013`)—prior to scheduling.
- **Alternatives Considered:** Scanning all `2,500` students on every `(course, candidate_session)` check inside the inner loop of `ALG-06`.
- **Rationale:** Reduces inner-loop student clash verification from $\mathcal{O}(S)$ to $\mathcal{O}(|C_{\text{session}}|)$ ($\le 15$ set lookups), accelerating scheduling by $>100\times$ while making `EC-07` conflict relationships explicit and inspectable.
- **Consequences:** Requires $\mathcal{O}(C^2)$ memory ($\le 14,400$ pairs for `120` courses — negligible).

## ADR-008 — Coupled Hall-Packability Verification Inside Greedy Scheduling (`ALG-06` + `ALG-08`)
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Verify exact physical hall, duration (`2h`/`3h`), alternate-column, `< 10` merge, and ground-floor Row 1 feasibility (`ALG-08`) during each candidate session check in `ALG-06`, rather than checking only the aggregate 90% seat count during `FR-02`.
- **Alternatives Considered:** Two-phase decoupled pipeline (schedule all courses using only 90% aggregate seat sum, then attempt hall allocation later).
- **Rationale:** Aggregate 90% capacity does **not** imply physical hall packability (e.g., `2h` and `3h` courses cannot share halls; single courses use only odd columns; special-needs students require ground-floor Row 1). Coupled `ALG-08` trial packing prevents downstream `FR-03` crashes without altering `BR-03` greedy ordering.
- **Consequences:** `scheduling/scheduler.py` depends on the stateless `HallPackabilityChecker` protocol implemented by `allocation/`.

## ADR-009 — Copy-on-Write Candidate Snapshots & Cryptographic Blast-Radius Verification (`ALG-19`)
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Execute every incremental `ChangeCommand` (`FR-05`) on an isolated copy-on-write `ScheduleState` clone, recomputing **only** `affected_sessions`, and asserting SHA-256 canonical digest equality on all unaffected sessions before atomic commit.
- **Alternatives Considered:** (1) In-place mutation with manual undo logs; (2) Full-window rescheduling after every command.
- **Rationale:** Full rescheduling violates `BR-09`–`BR-11` (*"Recompute only affected assignments"*). Manual undo logs are notoriously bug-prone when multi-course late registrations fail midway (`AS-030`). Immutable per-session tuples make snapshot cloning $\mathcal{O}(M)$ (`< 0.1 ms`) and rollback instantaneous.
- **Consequences:** All assignment dataclasses must remain strictly immutable (`frozen=True`).

## ADR-010 — Universal Lexicographical Tie-Breaking & Integer Arithmetic
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Terminate every sort key with a unique primary identifier (`course_code`, `hall_id`, `building_code`, `register_number`, `invigilator_id`), forbid unordered `set` iteration, and compute capacity/staffing thresholds with exact integer arithmetic (`(90 * cap) // 100`, `(n + 29) // 30`) and minute-from-midnight `TimeInterval` integers.
- **Alternatives Considered:** Floating-point `0.9 * cap`, `datetime.timedelta` arithmetic, or relying on input CSV row order.
- **Rationale:** Guarantees cross-platform, cross-`PYTHONHASHSEED` determinism (`NFR-01`) and eliminates floating-point rounding bugs (`EC-03`).
- **Consequences:** Enforced via Ruff lint rules and `TC-108` / `TC-109` regression gates.

## ADR-011 — Zero-Shared-Code Independent Schedule Validator (`ALG-18`)
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Build `src/exam_engine/validation/validator.py` importing **only** `domain/`, re-checking `BR-01`–`BR-12` independently after initial synthesis and before committing every incremental change.
- **Alternatives Considered:** Relying solely on unit tests of the constructive engines.
- **Rationale:** If a constructive helper has a subtle off-by-one bug, reusing that helper in validation masks the bug. Independent validation catches any invariant breach immediately at runtime (`40`-mark correctness insurance).
- **Consequences:** ~300 lines of clean verification logic maintained by Mishael (`M5`/`M7`).

## ADR-012 — Adapter-Isolated Provisional File Schemas & Policy Encapsulation
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Isolate all provisional CSV/JSON/TXT schemas (`10_INPUT_OUTPUT_CONTRACTS.md`) behind `io/` and `reporting/` adapters, and isolate the 33 specification assumptions (`05_ASSUMPTION_REGISTER.md`) in named policy classes rather than CLI flags.
- **Alternatives Considered:** Exposing 30+ CLI switches (`--round-mode`, `--chief-dept-ban`, etc.) or hardcoding column names inside engines.
- **Rationale:** Master Prompt Section 9 explicitly warns *"Do not create arbitrary configuration options for every assumption. Isolate important policy decisions in appropriate validators or policy components."*
- **Consequences:** Adapting to official sample schemas in Week 2/3 touches only `io/`, `reporting/`, and policy constants.

## ADR-013 — Five-Tier Pytest Strategy Without Heavy Property Frameworks Required
- **Date:** 2026-11-25 | **Status:** Proposed
- **Decision:** Standardise on `pytest` across 5 testing tiers (Unit, Integration, Seeded Generative Invariants, `PYTHONHASHSEED` Determinism, and Full-Scale Performance) traceable to `TC-001`–`TC-112`.
- **Alternatives Considered:** `unittest` stdlib runner only, or mandatory external fuzzing frameworks.
- **Rationale:** `pytest` fixtures and parametrisation keep 112 tests concise and readable for all 3 teammates during viva inspections.
- **Consequences:** Every PR in Weeks 2–3 must pass `pytest` and `ruff check` before merge.
